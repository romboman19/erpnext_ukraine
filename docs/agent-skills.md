# Скіли агентів у цьому репозиторії

У репозиторії лежать скіли для AI-агентів розробки — набір від команди Frappe.
Вони версіонуються разом із кодом, тому кожен, хто відкриває цей чекаут
(розробник або агент), отримує ті самі інструкції, без ручного встановлення.

## Що встановлено

Джерело: [`frappe/skills`](https://github.com/frappe/skills), коміт `ee6e615`,
встановлено 10.10.2026 через `npx skills add frappe/skills` (режим `--copy`,
тобто файли скопійовані, а не підвʼязані симлінками на тимчасову теку).

Файли: `.claude/skills/<назва>/`. Контрольні суми: `skills-lock.json` у корені.

| Скіл | Для чого | Запуск |
| --- | --- | --- |
| `frappe-app-dev` | Повний стек Frappe: DocType, контролери, API, ORM, hooks, права, черги, realtime, кеш, тести, `bench` і керування site | автоматично |
| `frappe-code-review` | Чек-лист рев'ю застосунку Frappe: коректність, безпека, продуктивність, конкурентність, читність, дизайн API, тести | автоматично |
| `code-style` | Загальні правила стилю коду | автоматично |
| `technical-writing` | Документація, README, коміти, PR, release notes у Simplified Technical English | автоматично |
| `ui-design` | Загальні принципи UI/UX | автоматично |
| `fix-issue` | Виправлення багу з GitHub issue без затягування шуму репорту в основний контекст | `/fix-issue` |
| `resolve-backport-conflicts` | Розбір конфліктів у backport-PR від Mergify | `/resolve-backport-conflicts` |
| `draft-security-advisory` | Чернетка GitHub Security Advisory (GHSA) з репорту про вразливість | `/draft-security-advisory` |
| `deep-app-audit` | Багатоагентний аудит застосунку на безпеку, коректність і дефекти кастомізації | `/deep-app-audit` |

## Межі, які скіли не скасовують

Скіли виконуються з повними правами агента, тому порядок такий: інструкції
агента (`AGENTS.md`) і правила цього репозиторію — головніші за будь-який скіл.
Зокрема:

- **`technical-writing` не стосується українських текстів продукту.** Мітки
  полів, повідомлення валідації, `uk` переклади і доки в `docs/` пишемо
  українською, як і раніше. Скіл застосовуємо до англомовних PR, комітів і
  README.
- **`frappe-app-dev` не вирішує, яка норма закону діє.** Ставки, групи ЄП,
  звільнення і дати набрання чинності лишаються даними в `UA Tax Parameters` та
  полях профілю з `verified_on` і джерелом. Хардкод ставки — дефект навіть тоді,
  коли число сьогодні правильне.
- **Жоден скіл не дає права писати в прод.** `erp.huntervua.pp.ua`, `bench` на
  живому site, контейнери, `.env`, ключі КЕП — зона ІТ спеціаліста.
- **`deep-app-audit` коштує грошей і вимагає bench.** Він підіймає тестовий site
  і запускає ~160 окремих процесів агента. Запускати тільки на staging-копії і
  тільки після погодження зі СЕО — не як частину звичайної правки.

## Як оновити

```bash
npx skills update --project          # усі скіли проєкту до останніх версій
npx skills add frappe/skills --skill frappe-app-dev --copy -y   # один скіл
npx skills ls                        # що встановлено
```

Оновлення — окремий коміт: у diff видно, що саме змінилося в інструкціях.
Після оновлення звірити, що `skills-lock.json` оновився разом із файлами.

## Чого тут немає

`.claude/settings.local.json` не версіонується (`.gitignore`): там абсолютні
шляхи і дозволи конкретної машини. Скіли, які Paperclip підкладає своїм агентам
у runtime, живуть поза репозиторієм і цим набором не керуються.
