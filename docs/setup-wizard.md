# Готовність до роботи після встановлення

Мета: після `bench install-app erpnext_ua` на чистому сайті адміністратор не
шукає, що ще налаштувати. Частину роботи застосунок робить сам, решту показує
списком і виконує покроково.

## Що застосунок робить сам

Це те, що не залежить від конкретного платника, тому виконується у
`after_install` та `after_migrate` без запитань:

- централізований український каталог перекладу (18 тис. рядків);
- повний комплект податкових параметрів року для груп 1–3: МЗП, прожитковий
  мінімум, ліміти доходу, ЄП, ЄСВ, військовий збір, дата перевірки й офіційні
  джерела;
- каталог засобів оплати з кодами форм ДПС: готівка й картка активні, решта
  каналів заведені, але вимкнені до перевірки адміністратором;
- ролі каси, ПРРО, цінників і комісійної торгівлі;
- кастомні поля українського обліку, приймання, каси, ПРРО й цінників;
- друковані форми Print Designer і Jinja як резерв;
- інвентарний вимір власності для комісійного модуля;
- робочі простори, навігація й піктограми застосунку;
- стабільні `device_id` для наявних кас ПРРО — без жодного мережевого виклику.

Наприкінці встановлення у вивід bench друкується стан готовності: що вже
зроблено, чого бракує і що з цього блокує роботу.

## Що вимагає даних платника

Ці кроки застосунок не вигадує за вас: `UA Setup Wizard` (робочий простір
`UA FOP` → **Setup**). Кожен крок ідемпотентний — повторний запуск нічого не
дублює.

| Крок | Потрібні дані | Хто виправляє |
| --- | --- | --- |
| Компанія | країна `Ukraine`, валюта `UAH` | стандартний майстер ERPNext |
| План рахунків | 291 повний або 186 спрощений | майстер, з підтвердженням |
| Податкові ставки | фактична ставка ЄП груп 1–2, рік, дата й рішення конкретної громади | бухгалтер у кожному `FOP Profile` |
| Профіль ФОП | ПІБ, назва для ПРРО, РНОКПП, група ЄП, ставка | майстер |
| КВЕД | основний КВЕД | майстер (необов'язково) |
| Каса | склад, назва каси | майстер (створює й роздрібного покупця) |
| Каса ПРРО | фіскальний номер, локальний номер, назва й адреса точки | майстер |
| Підпис ПРРО | ключ КЕП, сервіс підпису | вручну, окремо |

## Два рівні готовності

Звіт розрізняє їх окремо, бо це різні бізнес-ситуації:

- **можна продавати** — закриті всі кроки рівня «обов'язково». Документи
  продажу, склад, каса працюють;
- **можна фіскалізувати** — додатково налаштовані каса ПРРО, ключ КЕП і сервіс
  підпису. Без цього роздрібний чек за готівку/картку пробити не можна.

Мова інтерфейсу та КВЕД позначені як рекомендовані: вони не блокують продаж.

## Чого майстер не робить свідомо

- **Не змінює країну й валюту наявної компанії.** Після першої проводки це вже
  переоцінка обліку, а не налаштування. Якщо у компанії є проводки, крок
  переходить у стан `blocked` з поясненням, а не пропонує кнопку.
- **Не замінює план рахунків компанії з проводками.** Той самий принцип:
  міграція діючої компанії — окремий проєкт вхідних залишків. Заміна плану
  делегується `UA Chart of Accounts Setup` разом із його підтвердженням і
  preflight, а не дублює слабшу перевірку.
- **Не створює демо-компанію й демо-дані.** Тестові дані, які потім треба
  вичищати з бойової бази, — не готовність, а прибирання.
- **Не завантажує ключі КЕП і не звертається до ДПС.** Реєстрація каси у ДПС і
  ключ підпису лишаються явними діями з окремими правами.
- **Не вмикає жоден зовнішній конектор.** Нова Пошта, банки, еквайринг,
  маркетплейси, SMS і Telegram мають власні Settings і вмикаються окремо; звіт
  лише показує, які з них уже активні.
- **Не вгадує ставку місцевої ради.** Автоматичні параметри для груп 1–2 містять
  загальнодержавний максимум. Перед go-live бухгалтер записує фактичну ставку,
  рік, дату перевірки та URL рішення громади в кожному `FOP Profile`; це окремі
  значення для кожного ФОП у Multi-FOP.

## Перевірка без Desk

```bash
bench --site <site> execute erpnext_ua.ua_setup.service.report_readiness
```

Read-only. Той самий звіт доступний через API `erpnext_ua.ua_setup.service.readiness`.

Логіка оцінювання — чиста функція над зібраним станом
(`erpnext_ua/ua_setup/readiness.py`), тому вона покрита звичайними unit-тестами
без сайту: `erpnext_ua/tests/test_ua_setup_readiness.py`.
