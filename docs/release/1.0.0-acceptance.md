# Release 1.0.0 acceptance — 2026-07-14

## Результат

Release candidate пройшов ізольоване приймання на Frappe `16.25.0`, ERPNext
`16.26.2` і окремих test sites. Production site, production containers та
production data не змінювалися.

## Автоматичні перевірки

- `ruff check`: PASS;
- Python compile та JSON parse всіх schema/report/workspace files: PASS;
- pure unit/domain suite: 110 tests + 2 subtests, PASS;
- Frappe app regression: 19 integration tests, PASS;
- Frappe unspecified-category regression: 106 tests, PASS;
- clean install: усі 31 application DocType synced, `after_install` PASS;
- повторна idempotent `bench migrate`: PASS;
- readiness diagnostics: `ready_for_acceptance`, `blocking_checks = []`;
- PEP 517 wheel build: PASS, package-data check підтвердив DocType, report і
  Workspace JSON у `erpnext_consignment_and_commission-1.0.0-py3-none-any.whl`.

## Перевірені бізнес-сценарії

- один SKU одночасно з `BUYOUT`, `DEFERRED_PURCHASE`, `COMMISSION` і
  `CONSIGNMENT`; списання одним глобальним FIFO за received datetime;
- atomic concurrent reservation без oversell, negative stock або дубльованого
  exact Serial;
- net sales, commission income, consignment retained income та partner debt;
- Stock Asset/Supplier payable для власного приймання;
- foreign-currency obligation, часткові платежі з різними курсами та exchange
  difference;
- Settlement Report, debt JE, Payment Entry binding і cancellation order;
- buyer return до й після settlement, adjustment та credit due;
- exact Serial/Batch receipt, sale, return, partner return і conversion;
- zero-value third-party receipt/return без GL;
- third-party → OWN conversion через exact issue + stock-updating Purchase
  Invoice і reversal;
- split POS routes, retry, print queue, compensation та manual-review boundary;
- idempotency replay/conflict для write APIs;
- Manager/User/Auditor permissions і Company-scope restrictions;
- financial integrity, partner balance, FIFO, sales financials і POS reports.

## Чисте встановлення

Перший rehearsal виявив Frappe v16 schema restriction: mandatory hidden field
без default не може синхронізуватися. `CC Allocation.request_fingerprint`
залишено mandatory/read-only, але показано у формі для аудиту. Після системної
перевірки всіх DocType JSON повторне чисте встановлення та друга міграція
пройшли без помилок.

Readiness підтвердила required apps, core ERPNext fields, усі application
DocTypes/fields, Inventory Dimension, ролі, Workspace та 11 database indexes.

## Відомі межі rollout

- release не є юридичною сертифікацією конкретного ПРРО/фіскального provider;
- provider adapter, credentials, callback і друк приймаються окремо;
- для точного per-unit COGS власного товару потрібна стандартна ERPNext
  Serial/Batch valuation identity; untracked valuation є warehouse-level;
- production rollout потребує backup, staging rehearsal з production-like
  accounts, бухгалтерське acceptance та пілот однієї Company/Location;
- feature gate за замовчуванням вимкнений і активується лише після цих gates.
